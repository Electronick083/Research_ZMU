Из 8 достоверных дампов (`512-1_a.bin`..`512-8_a.bin`) собран цельный 32-битный образ массива. Скрипт сборки: `D:\Claude\ZMU\build_image.py` → `image_AB.bin` / `image_BA.bin` (по 512 КБ).

## Опознание
Это ПЗУ авионики **Boeing ZMU**. В образе читаемый текст:
- `COPYRIGHT 1992-2001, THE BOEING COMPANY, ALL RIGHTS RESERVED.  2374-BCE-021-02`
- метки `ZMU EXEC`, `ZMU MAIN LOADER`, `Invalid Data`, `BL or ML FAULT`, `SWPN/HWPN MISMATCH`, `BFE parse length-failure from headend`, `ZMU 04-30-0110`.

## Структура (определена по читаемости образа, не трассировкой)
Порядок байтов в 32-битном слове УТОЧНЁН против [[eeprom-array-architecture]] — лейны чипов (5,6) и (7,8) переставлены (байт2<->байт3):
- байт0 (LSB, D7..D0):  банк A = chip1, банк B = chip2
- байт1 (D15..D8):       банк A = chip3, банк B = chip4
- байт2 (D23..D16):      банк A = chip7, банк B = chip8
- байт3 (MSB, D31..D24): банк A = chip5, банк B = chip6

Раскладка банков = **ДВЕ НЕПРЕРЫВНЫЕ ПОЛОВИНЫ** (банк = старший адресный бит). Чередование слов исключено — оно рвёт строки (макс. строка падает с 653 до 134 байт).

Перестановка найдена перебором всех 24 вариантов байтовых лейнов с оценкой по читаемости (токены BOEING/COPYRIGHT/COMPANY/...): победитель score=13, остальные 0. Однозначно.

## Содержимое банков
- Банк A (чипы 1,3,5,7): разреженный, энтропия 2.2, прогон ~37277 — код/таблицы.
- Банк B (чипы 2,4,6,8): плотный, энтропия 5.85, ~5.9% ASCII-текста — данные/строки.

## Процессоры на плате
Два CPU (со слов пользователя):
- **MC68302FE20C** — ядро 68000, шина данных 16 бит, 20 МГц.
- **MC68030FE25B** — полный 32-битный CPU, шина 32 бита, 25 МГц.
Оба Motorola 68k → **big-endian** (байт по младшему адресу = старший байт, D31–D24).

**Вывод: массив почти наверняка принадлежит MC68030** — память физически 32-битная (4 лейна, чтение одним словом по общему OE), что соответствует 32-битной шине 68030. У 68302 шина 16-битная.

## РЕШЕНО: порядок половин и принадлежность
По вектору сброса 68030 (big-endian) определён правильный образ — **`image_BA.bin`** (банк B в младших адресах 0x00000–0x3FFFF, банк A в старших):
- `0x00` SSP = `0x4000178A` (стек, RAM ~0x40000000)
- `0x04` PC  = `0x20001040` (точка входа, ROM замаплен на 0x20000000)
- `+0x08..0x3C` все = `0x200012A4` — единый обработчик исключений (классическая валидная таблица векторов).

`image_AB.bin` даёт мусор (ASCII "285W0550" — кусок строки серийника), т.е. неверен.

**Подтверждено: массив принадлежит MC68030, big-endian.** Карта памяти (из живой цепочки в AT28C256 #1, см. [[at28c256-chip1-verified]]):
- bank B (chips 2,4,6,8) → ROM окно `0x20000000`–`0x2003FFFF` (256 КБ); сюда указывает вектор сброса, entry `0x20001040`, обработчик исключений `0x200012A4`.
- bank A (chips 1,3,5,7) → ROM окно `0x30000000`–`0x3003FFFF` (256 КБ).
- ОЗУ/стек: регионы 0x00000000 и 0x10000000 (по 32К); SSP сброса `0x4000178A`.
- I/O: 0xE0000000, 0xE1000000.

УТОЧНЕНИЕ: два банка — это два ОТДЕЛЬНЫХ окна по 256 КБ (0x20000000 и 0x30000000), а не один непрерывный 512 КБ. В файле `image_BA.bin` они идут подряд (bankB, потом bankA) — порядок байтов и содержимое верны, но второй половине соответствует база 0x30000000.

ФИНАЛЬНЫЙ ОБРАЗ: `image_BA.bin` (512 КБ). Все вопросы по сборке закрыты. Сборка репродуцируема из дампов D00077 (`285W0027-1\Dump_D00077_OK\`, дефолт `build_image.py`): md5 `9b8c5c02bdbbf98c72f042a3bc9644cd` (перепроверено 2026-07-23, `check_rom_crc` PASS 5/0).

## Структура прошивки (начало реверса, по адресам из дескрипторов config-чипа)
Карта file-offset = CPU-адрес − 0x20000000 (банк B = первые 256 КБ файла):
- `0x20000000` (off 0): boot-таблица векторов 68030 (VBR=0 при сбросе), entry 0x20001040, обработчик 0x200012A4.
- `0x20006794` (off 0x06794): таблица данных, 12-байтные записи (`00 23 02 00`…).
- `0x20034800` (off 0x34800): ПРИКЛАДНАЯ таблица векторов — грузится в VBR. SP=0x40001520, entry=0x200390A4, обработчики→0x20039282.
- `0x200390A4` (off 0x390A4): СТАРТОВЫЙ КОД прошивки. `MOVE #$2700,SR` → дёргает HW-регистры в 0x6000xxxx → `LEA $20034800,A4; MOVEC A4,VBR` (ставит прикладную таблицу векторов) → `LEA $40001520,A7` (стек).
- `0x20039170` (off 0x39170): 68030-код (процедуры).
- `0x200354D0`: таблица указателей (счётчик 0x22 + список адресов 0x2003xxxx) — диспетчер.
- `0x2003E91F`: пусто/конец.

Каталог этих структур с их CRC32 лежит в живой цепочке config-чипа с 0x1D00 (её прибор и проверяет при старте). Копия @0x3F08 — устаревший снимок, не читается: [[config-copy-3f08]].

ОТКРЫТИЕ: код обращается к региону **0x60000000** (регистры 0x60001828, 0x6000184C), которого НЕТ в 6-региональной карте записи A — вероятно I/O или dual-port обмен со вторым CPU (MC68302).

См. [[x28c512-array-dumps]], [[eeprom-array-architecture]], [[project-status]].
