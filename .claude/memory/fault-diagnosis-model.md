Модель различения дефектов при чтении параллельных EEPROM. Проверена на 4 заведомо битых файлах (`512_err1..4`) 2026-06-09.

## Два класса дефектов — два детектора

| Дефект | Детерминирован? | Ловит «2 чтения в 2 файла» | Ловит статический анализ одного файла |
|--------|-----------------|----------------------------|----------------------------------------|
| **Обрыв / плавающая линия** (адрес или данные) | НЕТ — читается каждый раз по-разному | ✅ ДА (число несовпадений между файлами плавает) | ❌ по одному снимку обрыв от КЗ не отличить |
| **Замыкание линий** (D↔D, A↔A) | ДА | ❌ оба чтения совпадут байт-в-байт | ✅ корреляция пар линий / инвариантность к обмену адресных бит |
| **Полностью залипший бит данных** | ДА | ❌ | ✅ OR/AND по битплоскостям (уже в `check_dump.py`) |
| **Мёртвая адресная линия** | ДА | ❌ | ✅ тест периода 2^i (уже в `check_dump.py`) |

## Ключевые выводы

1. **«2 чтения» — детектор НЕДЕТЕРМИНИРОВАННЫХ дефектов** (обрыв, плавающий контакт). При обрыве линии каждое чтение даёт разный результат → два файла не совпадут, число несовпадений плавает. Это единственный надёжный способ отличить обрыв/плавающую линию.
2. **Замыкания ДЕТЕРМИНИРОВАНЫ** → «2 чтения» их пропустит (оба чтения идентичны). Нужен статический корреляционный анализ.
3. **По одному статическому файлу обрыв линии данных и её замыкание с соседом НЕРАЗЛИЧИМЫ** — оба дают коррелированные биты. Отличительный признак обрыва (нестабильность) живёт только МЕЖДУ чтениями.
4. Полная методика = «2 чтения» (обрывы/плавающие) + статический анализ (замыкания/залипания). Это две обязательные половины, не дублирование.

## Результат теста на err-файлах (2026-06-09)

Истина: err1=обрыв A1, err2=обрыв данных D6, err3=замыкание D6–D7, err4=замыкание A1–A2.

- `check_dump.py` (штатный) поймал только **1/4** (err1 — мёртвая A1). Замыкания (err3,err4) и обрыв данных (err2) пропустил.
- Ручным анализом установлены 3/4 точно (err1,err3,err4); err2 — линию D6 определил верно, но природу назвал «замыкание» вместо «обрыв» (по одному файлу иначе нельзя, см. п.3).

## Состояние инструмента (обновлено 2026-06-09)

ИСПРАВЛЕНО: в `check_dump.py` добавлены три проверки замыканий — теперь ловит 4/4 на err-файлах при 0 ложных срабатываний на всех валидных дампах:
- `check_data_shorts` — корреляция пар линий данных по гистограмме значений (флаг при >99.9% равны/противоположны + асимметрия «нет комбинации D_i=1,D_j=0» ⇒ D_i=1⇒D_j=1);
- `check_address_shorts` — инвариантность дампа к обмену пары адресных бит. ВАЖНО: флагает только если в проверяемой зоне ≥4 разных значений (иначе зона сплошных нулей даёт ложный плюс — так словился разреженный at28c256_2, защита добавлена);
- `check_value_diversity` — предупреждение при <256 уникальных значений и энтропии >4.0.

ПРИНЦИП (важно, по указанию пользователя): статика ловит ТОЛЬКО детерминированные дефекты (замыкания, полностью залипший бит, мёртвая линия mism==0 — жёсткие факты, не пороги). ОБРЫВЫ/плавающие линии статикой НЕ детектируются — это задача протокола «2 чтения» (линия проявит себя несовпадениями). Не подгонять статические пороги под обрыв: «почти не влияет (<1%)» осталось лишь мягкой подсказкой в строке линии, в ИТОГ НЕ выносится (иначе ложные срабатывания на разреженных/полупустых чипах). Поэтому err1 (обрыв A1) по одному файлу даёт «не обнаружено» — и это правильно.

Ограничение по природе: по одному файлу обрыв линии данных и её замыкание с соседом неразличимы (err2 помечается как «связь/обрыв», без уточнения) — для различения нужен протокол «2 чтения» (см. таблицу выше).

Тест: 4/4 битых файлов в итоге распознаются (err1 — через «2 чтения», err2/3/4 — статикой), 0 ложных на валидных дампах.
