Вся память (memory) должна храниться только внутри папки проекта (`D:\Claude\ZMU`), а не в дефолтном расположении `C:\Users\Polus18\.claude\projects\...`.

**Why:** Прямое указание пользователя. Пользователь хочет, чтобы память жила вместе с проектом.

**How to apply:** Все файлы памяти и индекс `MEMORY.md` создавать в `D:\Claude\ZMU\.claude\memory\`. Не писать память в домашнюю папку пользователя.

## ⭐ CLAUDE.md подключает правила автоматически (по требованию пользователя 2026-08-13)

В корне проекта лежит **`D:\Claude\ZMU\CLAUDE.md`** — Claude Code читает его сам в начале каждой сессии. Он импортами `@путь` подтягивает ЦЕЛИКОМ `MEMORY.md` и файлы правил (`verify-before-claiming`, `hardware-branch-separation`, `memory-edits-only-on-disproof`, этот файл, `diagnostic-design-principle`, `project-scripts-index`, `project-readme-file`), чтобы правила не приходилось вспоминать или искать.

**Почему так:** пользователь: «сделай так, чтобы правила проекта в следующих сессиях вначале работы читались полностью». До этого правила читались только если я сам открывал `MEMORY.md`, и часть сессии я работал, опираясь на пересказ по памяти.

**✅ ПРОВЕРЕНО ЭМПИРИЧЕСКИ 2026-08-13, а не взято из документации.** Три прогона `claude -p --tools "" --model haiku` из папки проекта: инструментов у той сессии не было вообще, читать файлы ей было нечем, и она процитировала содержимое ВСЕХ ВОСЬМИ импортов — первую строку блока правил, правило №3 из `hardware-branch-separation`, последнюю строку индекса (`tkinter-dpi-blur`), хвост `project-readme-file`, историю с `REC_A` из `project-scripts-index`, порог err1 из `diagnostic-design-principle`, список пропавших имён из `memory-edits-only-on-disproof` и свежие правки этого файла. Значит `CLAUDE.md` грузится сам и импорты раскрываются целиком, включая хвосты длинных файлов (`MEMORY.md` — 26 КБ, обрезки нет). Версия Claude Code 2.1.231.

⚠️ **Цена: ~68 КБ (примерно 16–17 тыс. токенов) в каждой сессии.** Это осознанный размен: правила в контексте с первой секунды. Пользователь может посмотреть фактическую загрузку командой `/context`.

⚠️ **Импорт внутри блока кода НЕ срабатывает** (парсер пропускает code spans и fenced blocks) — строки `@...` держать обычным текстом. Глубина вложенности импортов максимум 4 перехода; у нас 1.

## 🔔 Хук-сторож: `.claude/check_rules_loaded.py` (заведён 2026-08-13)

Ручной шаг «не забыть дописать импорт» подстрахован автоматикой. В `.claude/settings.json` заведён хук **`SessionStart`**, который запускает `.claude/check_rules_loaded.py`. Скрипт сам просматривает `.claude/memory/*.md`, отбирает правила по `type: feedback` и сверяет со списком импортов в `CLAUDE.md`:

- файл правила есть, а импорта нет → в контекст падает предупреждение со списком и требованием прочитать их Read'ом прямо сейчас;
- импорт есть, а файла нет (переименовали/удалили) → предупреждение о битом импорте;
- `CLAUDE.md` вообще отсутствует → предупреждение, что правила не загружены;
- всё в порядке → скрипт **молчит**, ни байта контекста не тратится.

Смысл: механизм ломается ГРОМКО, а не молча. Проверено 2026-08-13 на четырёх сценариях (здоровое состояние, новый неподключённый файл правила, битый импорт, откат) — все отработали. Ловушка, на которой скрипт сам споткнулся при отладке: `lstrip("./")` срезает любые символы из набора и превращает `.claude/...` в `claude/...` — нужен `removeprefix("./")`. Тест это поймал сразу.

**How to apply:**
- Появилось новое ПРАВИЛО в отдельном файле — добавить строку `@.claude/memory/<файл>.md` в `CLAUDE.md`. Забыли — хук напомнит в начале следующей сессии, но лучше не доводить.
- Переименовали/перенесли файл правил — поправить импорт, иначе он молча не подтянется. Проверка: все пути из `CLAUDE.md` должны существовать на диске.
- `CLAUDE.md` — точка входа, а НЕ копия правил. Текст правил в него не дублировать: источник истины один, в `.claude/memory/`.
- Записи с большим техническим объёмом (`fault-diagnosis-model`, `hwpn-vs-swpn`, `firmware-integrity-pipeline`, `ghidra-setup`) сознательно НЕ импортируются — на них в `CLAUDE.md` стоит список «открыть Read'ом по теме».

## Структура индекса (указание пользователя 2026-07-21)

`MEMORY.md` начинается блоком **«⚠️ ПРАВИЛА РАБОТЫ — читать первым»**, и только потом идут факты (статус → железо → прошивка → инструменты).

**Why:** методические правила лежали вперемешку с фактами, и при беглом чтении памяти я их проскакивал — пересказывал факты по проекту, а правила проверки выводов пропускал. Пользователь: «методические правила должны быть в индексе, чтобы при беглом прочтении памяти ты это видел».

**How to apply:**
- Строка в блоке правил формулирует **само правило** повелительно, а не название заметки. «Выборка: две оси, а не три блока» вместо «HWPN vs SWPN».
- Появилось новое методическое правило или урок из ошибки — строка идёт в верхний блок, а не в общий список. Несколько правил могут ссылаться на один файл ([[verify-before-claiming]] — самый частый источник).
- Содержимое заметок в индекс по-прежнему не переносить: одна строка = один указатель.
