# Разбор ПЗУ ZMU в Ghidra (headless)

Ghidra 12.1.2 (`C:\Tools\ghidra_12.1.2_PUBLIC`), JDK 21. Скрипты на Java —
компилируются Ghidra на лету, ставить ничего не надо.

## Запуск

```bash
cd D:/Claude/ZMU/ghidra
./run_analysis.sh ../image_BA.bin ../Dump_D00077_OK/at28c256_1.bin ZmuRefs2.java
```

Аргументы: образ ПЗУ 512 КБ, config-чип AT28C256 #1, дальше — любые скрипты.
Проект остаётся в `work/proj`, повторный прогон без переанализа:

```bash
"$GHIDRA/support/analyzeHeadless.bat" work/proj ZMU -process bankB.bin \
    -noanalysis -scriptPath . -postScript ZmuDump.java
```

Автоанализ ~25 с, находит ~630 функций / ~44000 инструкций.

## Карта памяти (ZmuMap.java, преСкрипт)

| блок | адрес | источник |
|---|---|---|
| ПЗУ банк B | `0x20000000` | образ, офсет `0x00000` (импортируется загрузчиком) |
| ПЗУ банк A | `0x30000000` | образ, офсет `0x40000` |
| config-чип | `0x00000000` | `at28c256_1.bin`, 32 КБ |
| ОЗУ | `0x10000000`, `0x40000000` | пусто |
| HW MC68302 | `0x60000000` | пусто, volatile |
| I/O | `0xE0000000`, `0xE1000000` | пусто, volatile |

Точка входа `0x20001040`. Config-чип виден коду по absolute-short
(`lea (0x1d00).w,A1`), поэтому и отображён в нижнюю память.

## Скрипты

- `ZmuMap.java` — карта памяти + точка входа. Всегда как `-preScript`.
- `ZmuRefs.java` — ссылки на конкретные диапазоны config-чипа (записи A и B).
- `ZmuRefs2.java` — все ссылки ИЗ ИНСТРУКЦИЙ в окно `0x0000..0x7FFF`:
  гистограмма по страницам + поиск непосредственных констант. Основной
  инструмент для вопроса «читает ли прибор такую-то область config-чипа».
- `ZmuDump.java` — дизасм ключевых функций + поиск констант косвенной адресации.
- `ZmuWalk.java` — для каждой ссылки на `0x1D00` печатает 26 инструкций подряд. Им видно
  ограничение обходчика цепочки и границы проверяемых блоков — так была найдена CRC карты
  памяти (`lea (0x2a,A4),A0 / lea (0x9f,A4),A2`).

## Гонять на КАЖДОЙ прошивке отдельно

У D00109 софт другой (банк B расходится с D00077 на 50–95%, а это код), поэтому вывод о
поведении прибора с одного образа на другой НЕ переносится:

```bash
./run_analysis.sh ../image_BA.bin ../Dump_D00077_OK/at28c256_1.bin ZmuRefs2.java ZmuWalk.java
./run_analysis.sh ../image_D00109_crash.bin ../Dump_D00109_crash/at28c256-1.bin ZmuRefs2.java ZmuWalk.java
./run_analysis.sh ../Dump_-101_D00636_OK/image_D00636.bin ../Dump_-101_D00636_OK/at28c256_1_285W0593-5_9805.bin ZmuRefs2.java ZmuWalk.java
```

Побочно: **config-чип содержит код** (`0x0000..0x1CFF`), часть проверок живёт прямо в нём
(`0x0BDC`, `0x16DA`, `0x16F6`, `0x17FC`).

## Оговорка по покрытию

Автоанализ дизассемблирует не весь массив (~44000 инструкций ≈ четверть 512 КБ).
Поэтому вывод «ссылок нет» подкреплять сырым байтовым сканом константы по всему
образу — отсутствие ссылок в Ghidra само по себе доказательством не является.
