Разобрано 2026-07-21 на шести экземплярах.

## Карта чипа

| диапазон | что там |
|---|---|
| `0x0000..0x018F` | **счётчики**: одно 16-битное значение, повторённое много раз подряд, затем следующее |
| `0x0190..0x01FF` | небольшая структура полей, дальше пусто |
| `0x0200..0x146D` | **снимки журнала**, по 256 байт каждый |
| `0x146E..0x7FFF` | нули (у D00109 данные кончаются раньше, на `0x136C`) |

### Счётчики `0x0000..0x018F`
Первое значение у каждого блока своё: D00077 `0x1906`, D00636 `0x1B84`, D00650 `0x1201`, D00669 `0x1C03`. Дальше по чипу идут ещё несколько (у D00636: `0x00D5`, `0x00D4`, затем `0x0017`, `0x0016`). Пары, отличающиеся на единицу, — счётчик инкрементируют записью в свежие ячейки, старое значение остаётся рядом (износовыравнивание). **Что именно считается — наработка, циклы включения, число событий — из дампа не выводится. Не выдумывать.**

### Снимки `0x0200..0x146D`
Каждый блок 256 байт — снимок состояния журнала. **Записи в каждом следующем блоке сдвинуты на 2 байта раньше**: `0x0300`→`+0x50`, `0x0400`→`+0x4E`, `0x0500`→`+0x4C`, … `0x1400`→`+0x2E`. Самый свежий снимок — последний.

Внутри снимка:
- **кольцевой буфер на 5 записей**, формат `[6 байт BCD ГГ ММ ДД ЧЧ ММ СС] [3 байта код] [3 байта параметр]`;
- **таблица с фиксированными слотами** (`0x0D78..0x0E39` в базовом снимке), формат `[2 байта][6 BCD][3 код][1 байт]`, до 17 слотов — каждый держит дату последнего срабатывания своего типа.

## ⚠️ История ГЛУБЖЕ пяти записей

Первоначальный вывод «видны только последние 5 событий» **НЕВЕРЕН и снят**. Раз каждый снимок хранит своё состояние, **старые снимки сохраняют вытесненные записи**. Сбор по всему чипу с проверкой кода даёт 23–27 уникальных записей на блок, вплоть до 1994 года.

Метод: сканировать весь чип, требуя, чтобы поле кода принадлежало известному набору (`151e71`, `151e73`, `89604c`, `89604e`, `89604f`, `7bf00b`) и поля BCD были валидны. Без фильтра по коду получается мусор — см. раздел об ошибке ниже.

## Снятое по блокам (2026-07-21)

| блок | состояние | свежая часть журнала |
|---|---|---|
| D00077 (`-1`) | рабочий | пять записей за 2024 г., код `151e71` |
| D00636 (`-101`) | рабочий | 2025-12-16, 2026-01-22, 01-23 ×2, 01-30, **2026-05-24** |
| D00650 (`-101`) | не работает | 2025-07-12, 08-01, 09-19, **09-30 (параметр 02)**, 10-22, **10-28 (параметр 02)** |
| D00669 (`-101`) | не работает | 2025-12-16, пять записей 08.01.2026 за 28 минут, 2026-01-21 |
| D00109 (`-1`) | reboot loop | журнала нет вовсе (26 ненулевых байт на весь чип) |
| D00092 (`-1`) | не работает | журнал **стёрт в `FF`**, записей 0 |

Байт параметра обычно `00`. У D00650 он дважды `02` — на двух последних месяцах перед снятием с борта. Это единственное, чем его журнал отличается ПО ФОРМЕ от журнала исправного блока. Семантика неизвестна.

## ⭐ D00636 и D00669 — похоже, стояли на ОДНОМ БОРТУ (гипотеза)

Ключевая запись, обе по одному адресу `0x0B1C`, поодиночке среди нулей:

```
D00636 (рабочий):  25 12 16 07 02 59 15 1E 73 0E 00 40   -> 16.12.2025 07:02:59
D00669:            25 12 16 07 03 01 15 1E 73 0E 00 40   -> 16.12.2025 07:03:01
```

Одинаковые код и параметр `0E 00 40`, расхождение ровно **две секунды**. Плюс девять совпадающих меток 2007–2008 гг. в таблице слотов. При этом собственные записи у них разные: `2007-07-14` у D00636 в `05:08:02`, у D00669 в `07:29:33`; записи 1994 г. свои у каждого; у D00669 есть `2007-03-01` и `2010-01-09`, которых нет у D00636.

**Читается как два блока на одном борту:** общесистемные события фиксируются одновременно и с одинаковой меткой (время в салонной сети раздаётся централизованно), собственные — врозь. Двухсекундная разница показывает, что метки получены независимо, а не скопированы.

❌ **Заменяет прежнюю гипотезу «заводская преинициализация таблицы слотов»** — та не объясняла ни расхождений, ни двухсекундной разницы. Обе были гипотезами; эта объясняет больше.

У D00650 коды другие (`7bf00b` вместо `89604f`) и общих меток ни с кем нет — похоже, он с другого борта.

## ⚠️ Как НЕ ошибиться (ошибка уже допущена)

**Не сканировать BCD-метки на каждом смещении без фильтра по коду события.** Так сделал я 2026-07-21 и получил «15 совпадающих записей до секунды» у D00636 и D00669 — на этом основании объявил один блок клоном другого. Вывод неверен и снят: журналы разных блоков совпадают по служебной структуре, скользящее окно вылавливает «записи» из неё. Разбор — [[unit-d00669]], [[verify-before-claiming]].

**Разрыв между последней записью и снятием блока с борта сам по себе НИЧЕГО не доказывает.** У исправного D00636 в журнале есть пропуск почти в четыре месяца (30.01.2026 → 24.05.2026). Вывод «обрыв журнала = дата отказа» я сделал по D00650 и снял.

**Код `151e7x` пишут и ИСПРАВНЫЕ блоки** — это не аварийный код. Семантику кодов из дампов извлечь нельзя: в прошивке таблицы расшифровки нет, нужна сервисная документация.
